🎯 What is Sage?

Sage is a production-grade HR policy chatbot that answers employee questions using company policy documents as its single source of truth.

📋 The Problem

Employees constantly ask HR the same questions — leave balance, notice period, WFH rules. HR teams spend hours answering repetitive queries instead of doing strategic work.

💡 The Solution

Sage ingests company HR policy documents, understands them semantically, and gives instant cited answers 24/7. Every answer links back to the exact policy section it came from.

🏢 Real-World Relevance

RAG-based Q&A is the #1 enterprise AI use case in 2024-2026. Every company with internal docs needs this. Sage demonstrates the full production pattern.

Agent Details

🔀 Router Agent

Uses Strands + Gemini to classify queries. HR queries proceed to retrieval; non-HR queries get a polite rejection. Falls back safely on failure (treats as non-HR).

🔍 Retriever Agent

Performs hybrid search combining ChromaDB vector similarity and BM25 keyword matching, merged via Reciprocal Rank Fusion (RRF). Returns top-5 most relevant policy chunks.

✍️ Answer Agent

Uses Strands + OpenAI-compatible LLM to generate concise, cited answers strictly grounded in retrieved chunks. Includes conversation history for follow-up resolution.

✅ Validator Agent

Checks if the generated answer is actually supported by the retrieved chunks. If not grounded, triggers a retry with corrective feedback to improve accuracy.

🔎 Hybrid Search: Why Not Just Embeddings?

Most RAG demos use only vector similarity search. Sage combines two approaches for significantly better retrieval quality.

📐 Vector Search (ChromaDB)

Encodes queries into 384-dim embeddings using all-MiniLM-L6-v2. Finds semantically similar chunks even if they don't share exact keywords. Great for "what are the WFH rules?" → finds "work from home policy".

📝 BM25 Keyword Search

Classic TF-IDF-based ranking that excels at exact term matching. Critical for specific queries like "Band B notice period" where the exact terms matter.

🔗 Reciprocal Rank Fusion (RRF)

Merges both result lists using: score = Σ(1 / (k + rank_i)). Deduplicates by chunk ID and returns top-5. Gets the best of both worlds — semantic understanding + keyword precision.

⚡ Why Strands SDK Instead of LangGraph?

This was a deliberate architectural decision based on the nature of the agent pipeline.

The Key Insight

Sage's agent pipeline is linear and sequential: Classify → Retrieve → Generate → Validate. There are no cycles, no dynamic branching where agents call each other in loops, and no complex state machines. For this pattern, Strands is the right tool.

Aspect AWS Strands Agents SDK LangGraph
Complexity Minimal — Agent(model, prompt) and call it Define StateGraph, nodes, edges, conditional edges
Best for Sequential pipelines, single-purpose agents Cyclical workflows, agents that loop/branch dynamically
Orchestration Plain Python (async/await, if/else) Graph-based state machine
Boilerplate ✓ Minimal — ~5 lines to create an agent ✗ Heavy — graph definition, state schemas, node functions
Dependencies Lightweight — just strands-agents Heavy — entire LangChain ecosystem
Model providers Google Gemini, OpenAI, Bedrock, Anthropic LangChain-wrapped providers
Flexibility Full control over flow, no framework lock-in Must fit into graph paradigm
When to avoid Complex multi-turn agent loops with dynamic routing Simple sequential pipelines (overkill)

💬 Interview-Ready Answer

"I chose AWS Strands Agents SDK because my pipeline is sequential — classify, retrieve, generate, validate. Strands gives a clean agent abstraction with Agent(model, prompt) and I orchestrate them with plain Python async/await. LangGraph's state machine approach would add unnecessary complexity for a linear flow. If I needed agents dynamically deciding which other agent to call in a loop (like an autonomous research agent), LangGraph would be the right choice. For a structured RAG pipeline, Strands keeps the code simple, readable, and framework-agnostic."

✨ Key Features

🔐 Authentication & RBAC

JWT-based auth with role-based access control. Three roles: employee, hr_admin, admin. Admins can view analytics and manage users.

⚡ Real-time Streaming

WebSocket-based token streaming for instant feedback. Answers appear word-by-word like ChatGPT, with HTTP POST fallback for reliability.

📎 Inline Citations

Every answer includes [Document - Section] citations linking back to the exact policy paragraph. Users can verify any claim.

🛡️ Prompt Injection Guard

Input validation layer detects and blocks prompt injection attempts before they reach the LLM. Protects against adversarial inputs.

📄 PDF Upload

Users can upload their own PDFs and ask questions about them. Documents are chunked, embedded, and searchable alongside HR policies.

👍 Feedback Loop

Thumbs up/down on every response, stored in PostgreSQL. Enables continuous improvement and RLHF-style quality tracking.

🏎️ Rate Limiting

In-memory sliding window rate limiter (20 requests/minute per user). Prevents abuse without external dependencies like Redis.

📊 Observability

Langfuse integration for tracing LLM calls, retrieval quality, and latency. Request IDs on every call for end-to-end debugging.

🔄 End-to-End Data Flow

Here's exactly what happens when an employee asks "How many casual leaves do I get per year?"

Step-by-Step Flow

  • 1. Input Validation — Query is checked for length (1–1000 chars) and scanned for prompt injection patterns
  • 2. Router Agent — LLM classifies the query as HR-related (confidence: 0.95, category: "leave")
  • 3. Query Embedding — Query is encoded into a 384-dimensional vector using all-MiniLM-L6-v2
  • 4. Vector Search — ChromaDB returns top-10 semantically similar chunks (cosine similarity)
  • 5. BM25 Search — Keyword index returns top-10 matching chunks by term frequency
  • 6. RRF Fusion — Both lists are merged, deduplicated, and top-5 chunks are selected
  • 7. Answer Generation — LLM receives chunks + query + conversation history → generates cited answer
  • 8. Validation — Validator checks if every claim in the answer is supported by the chunks
  • 9. Streaming — Answer is streamed token-by-token to the frontend via WebSocket
  • 10. Storage — Exchange is saved to session history for follow-up context resolution
