🔄 End-to-End Data Flow

What happens when you ask "How many casual leaves do I get?"

1
Input Validation — Query checked for length (1–1000 chars) and scanned for prompt injection patterns
2
Router Agent — LLM classifies as HR-related (confidence: 0.95, category: "leave")
3
Query Embedding — Encoded into 384-dimensional vector using all-MiniLM-L6-v2
4
Vector Search — ChromaDB returns top-10 semantically similar chunks (cosine similarity)
5
BM25 Search — Keyword index returns top-10 chunks by term frequency
6
RRF Fusion — Both lists merged, deduplicated, top-5 chunks selected via Reciprocal Rank Fusion
7
Answer Generation — LLM receives chunks + query + conversation history → generates cited answer
8
Validation — Validator checks if every claim is supported by chunks; retries if hallucinated
9
Streaming — Answer streamed token-by-token via WebSocket to the frontend
10
Storage — Exchange saved to session history for follow-up context resolution

🔎 Hybrid Search Strategy

Sage doesn't rely on a single retrieval method. It combines two complementary approaches for better recall and precision:

MethodHow it worksStrength
Vector Search (ChromaDB)Encodes query into 384-dim embedding, finds cosine-similar chunksSemantic understanding — finds relevant chunks even without exact keyword match
BM25 Keyword SearchTF-IDF based term frequency ranking over tokenized chunksExact term matching — critical for "Band B notice period" style queries
Reciprocal Rank Fusionscore = Σ(1 / (k + rank_i)) — merges both lists, deduplicatesBest of both worlds — semantic + keyword precision in top-5 results
